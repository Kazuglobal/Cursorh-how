## 1. Cursor とは何か

### 概要

Cursor は **Anysphere 社** が開発した AI ファーストのコードエディタである。Visual Studio Code（VSCode）をフォークして構築されており、VSCode の全機能（拡張機能、テーマ、キーバインド、設定）をそのまま利用できる。AI によるコード補完、チャット、コード生成、リファクタリング支援などを統合的に提供し、開発者の生産性を大幅に向上させることを目的としている。

### 基本情報

| 項目 | 内容 |
|------|------|
| 開発元 | Anysphere Inc. |
| ベース | Visual Studio Code（VSCode フォーク） |
| 初回リリース | 2023年 |
| ライセンス | プロプライエタリ（無料プランあり） |
| 公式サイト | https://www.cursor.com/ |
| ドキュメント | https://docs.cursor.com/ |

### 対応 OS

| OS | 対応状況 |
|----|----------|
| Windows | 対応（x64） |
| macOS | 対応（Intel / Apple Silicon） |
| Linux | 対応（.AppImage / .deb） |

### VSCode との違い

- **AI ネイティブ統合**: コード補完、チャット、エージェントモードが組み込み済み
- **コンテキスト認識**: プロジェクト全体のコードベースをインデックスし、AI がコンテキストを理解
- **マルチモデル対応**: Claude Opus 4.6、Sonnet 4.5、GPT-5.3、Composer など複数の LLM を選択可能
- **プライバシーモード**: コードをリモートに送信しない設定が可能
- **Composer / Agent**: 複数ファイルにまたがる大規模な変更をAIが自動実行

## 2. インストールとセットアップ

### 2.1 ダウンロード

1. [https://www.cursor.com/](https://www.cursor.com/) にアクセス
2. OS に合わせたインストーラをダウンロード
   - Windows: `.exe` インストーラ
   - macOS: `.dmg` ファイル
   - Linux: `.AppImage` または `.deb`
3. インストーラを実行し、画面の指示に従う

### 2.2 初期設定

初回起動時にセットアップウィザードが表示される。

1. **テーマ選択**: ライト/ダークテーマを選択
2. **キーバインド設定**: VSCode / Vim / Emacs / Sublime Text など既存エディタのキーバインドをインポート可能
3. **VSCode 拡張機能のインポート**: 既存の VSCode 拡張機能をワンクリックでインポート
4. **AI モデルの選択**: 使用するデフォルト AI モデルを選択
5. **アカウント作成/ログイン**: メール、GitHub、または Google アカウントで登録

### 2.3 VSCode からの移行

Cursor は VSCode フォークのため、移行が極めて簡単。

```
移行手順:
1. Cursor を初回起動
2. セットアップウィザードで「Import from VSCode」を選択
3. 以下が自動インポートされる:
   - 拡張機能（Extensions）
   - テーマ（Themes）
   - キーバインド（Keybindings）
   - 設定（Settings）
   - スニペット（Snippets）
```

**注意点:**
- VSCode と Cursor は同時にインストール・実行可能
- 拡張機能は VSCode Marketplace のものがそのまま使える
- 一部の AI 系拡張機能（GitHub Copilot 等）は Cursor の AI 機能と競合する可能性がある

## 3. 主要機能

### 3.1 Tab 補完（Cursor Tab）

Cursor の最も基本的な AI 機能。コードを書いている最中に、AI がリアルタイムで次のコードを予測・提案する。

**特徴:**
- **単行補完**: 現在の行の続きを予測
- **複数行補完**: 関数全体やコードブロックの自動生成
- **コンテキスト認識**: 現在のファイル、インポート済みモジュール、プロジェクト構造を理解
- **編集予測**: カーソル位置だけでなく、次に編集すべき箇所を予測して提案

**操作方法:**

| 操作 | キー |
|------|------|
| 補完を受け入れ | `Tab` |
| 補完を拒否 | `Esc` |
| 単語単位で受け入れ | `Ctrl + →`（Windows/Linux） / `Cmd + →`（macOS） |
| 次の候補を表示 | 自動的に更新される |

**設定:**
- `Cursor Settings` > `Cursor Tab` で有効/無効を切り替え
- ファイルタイプごとに有効/無効設定が可能

### 3.2 Cmd+K / Ctrl+K（インラインエディット）

選択したコードに対して自然言語で指示を出し、AI にその場で編集させる機能。

**使い方:**

1. 編集したいコードを選択（選択しない場合は新規コード生成）
2. `Ctrl + K`（Windows/Linux）または `Cmd + K`（macOS）を押す
3. インラインプロンプトバーが表示される
4. 自然言語で指示を入力（例:「この関数にエラーハンドリングを追加して」）
5. AI が差分を生成・表示
6. `Enter` / `Ctrl + Enter` で適用、`Esc` でキャンセル

**活用例:**
```
- 「この関数をTypeScriptに変換して」
- 「パフォーマンスを改善して」
- 「コメントを日本語で追加して」
- 「この条件分岐をswitch文に変えて」
- 「エラーハンドリングを追加して」
```

### 3.3 Chat（AI チャット）

サイドパネルでAIとチャット形式で対話する機能。コードの質問、説明、デバッグ支援に使う。

**起動方法:**
- `Ctrl + L`（Windows/Linux）/ `Cmd + L`（macOS）

**特徴:**
- プロジェクト全体のコードベースを参照して回答
- コードスニペットを直接チャットに貼り付け可能
- AI の回答をそのままエディタに適用できる（Apply ボタン）
- 会話履歴の保持と新規チャット作成
- `@` 記号でコンテキストを明示的に追加可能

**コンテキスト参照（`@` シンボル）:**

| 記法 | 参照先 |
|------|--------|
| `@file` | 特定のファイル |
| `@folder` | 特定のフォルダ |
| `@code` | 特定のコードシンボル（関数、クラスなど） |
| `@web` | ウェブ検索結果 |
| `@docs` | ドキュメント（カスタム登録可能） |
| `@git` | Git の差分・コミット履歴 |
| `@codebase` | プロジェクト全体のコードベース |
| `@definitions` | シンボルの定義元 |
| `@paste` | クリップボードの内容 |

### 3.4 Composer（コンポーザー）

複数ファイルにまたがる大規模なコード変更を一括で行う機能。Chat の進化版で、プロジェクト全体を対象にした操作が可能。

**起動方法:**
- `Ctrl + I`（Windows/Linux）/ `Cmd + I`（macOS）

**特徴:**
- 複数ファイルの同時作成・編集・削除
- 新規ファイルの自動生成
- プロジェクト構造の認識
- 差分のプレビューと段階的な適用

**活用例:**
```
- 「ユーザー認証機能を実装して。サインアップ、ログイン、パスワードリセットのAPIとフロントエンドを作成して」
- 「このプロジェクトにダークモードを追加して」
- 「テストファイルを全コンポーネントに追加して」
- 「APIレスポンスの型定義を全ファイルで統一して」
```

### 3.5 Agent モード

Composer の上位機能。AI が自律的にコードを読み、ターミナルコマンドを実行し、エラーを修正しながらタスクを完了する。

**特徴:**
- **自律実行**: AI がファイルの読み書き、ターミナル操作を自動実行
- **エラー自動修正**: ビルドエラーやリントエラーを自動的に検出・修正
- **ツール使用**: ファイルシステム操作、ターミナルコマンド、ウェブ検索などのツールを使用
- **段階的実行**: 各ステップでユーザーに確認を求めるオプション
- **コンテキスト自動取得**: 必要なファイルを自律的に検索・参照

**Agent モードの起動:**
- Composer 内でモードを「Agent」に切り替える
- プロンプトに対して AI が計画を立て、段階的にタスクを実行

**使用上の注意:**
- 破壊的な操作（ファイル削除、ターミナルコマンド）は確認を求められる
- 大規模な変更前には Git コミットを推奨
- Agent モードは Premium リクエストを多く消費する

### 3.6 コンテキスト管理

Cursor の AI 機能の精度は、提供するコンテキストの質に大きく依存する。

**自動コンテキスト:**
- 現在開いているファイル
- 最近編集したファイル
- インポート/参照しているファイル
- カーソル周辺のコード

**手動コンテキスト追加:**
- `@` シンボルによる明示的参照（前述）
- ファイルのドラッグ&ドロップ
- コードの選択とチャットへの送信
- `.cursorrules` によるプロジェクト規約の指定

**コードベースインデックス:**
- プロジェクト全体を自動インデックス化
- セマンティック検索（意味ベースの検索）が可能
- `@codebase` で明示的にプロジェクト全体を参照
- `.cursorignore` で除外ファイルを指定可能

### 3.7 モデル選択

Cursor は複数の AI モデルに対応しており、タスクに応じて使い分けられる。

**対応モデル（2026年2月時点）:**

| モデル | 提供元 | 特徴 | 推奨用途 |
|--------|--------|------|----------|
| Claude Opus 4.6 | Anthropic | 最高品質、1Mコンテキスト（ベータ） | 複雑な推論、大規模リファクタリング |
| Claude Sonnet 4.5 | Anthropic | コーディングに最適 | 日常的なコーディング、リファクタリング |
| GPT-5.3 | OpenAI | OpenAI 最新モデル | 高品質コード生成 |
| GPT-4o | OpenAI | 高速・汎用 | 一般的なコーディング、チャット |
| GPT-4o mini | OpenAI | 高速・低コスト | 軽量なタスク |
| Gemini 3 Pro | Google | Google 最新モデル | マルチモーダルタスク |
| Composer | Cursor 独自 | Sonnet 4.5 同等品質、2倍速 | コーディング全般（デフォルト） |
| cursor-small | Cursor 独自 | 軽量・高速 | Tab 補完、高速応答 |

**モデル切り替え:**
- チャット/Composer ウィンドウ下部のモデルセレクタで変更
- `Cursor Settings` > `Models` でデフォルトモデルを設定
- API キー入力で OpenAI / Anthropic / Google / Azure の独自キーを使用可能

## 4. 設定とカスタマイズ

### 4.1 .cursorrules（プロジェクトルール）

プロジェクトのルートに `.cursorrules` ファイルを配置することで、AI にプロジェクト固有の規約やコーディングスタイルを指示できる。

**配置場所:** プロジェクトルート（`.cursorrules`）

> **注意:** 新しいバージョンの Cursor では `.cursor/rules/` ディレクトリ配下に複数のルールファイルを配置する形式（Project Rules）が推奨されている。`.cursorrules` は引き続きサポートされているが、将来的に `.cursor/rules/` 形式への移行が推奨される。

**記述例:**

```markdown
# .cursorrules

## プロジェクト概要
このプロジェクトは Next.js 14 + TypeScript + Tailwind CSS のウェブアプリケーションです。

## コーディング規約
- TypeScript strict モードを使用
- 関数コンポーネントと React Hooks のみ使用（クラスコンポーネント不可）
- 状態管理には Zustand を使用
- CSS には Tailwind CSS のユーティリティクラスのみ使用
- 全ての関数に JSDoc コメントを記述

## ファイル構成
- components/ - 再利用可能なUIコンポーネント
- app/ - Next.js App Router のページ
- lib/ - ユーティリティ関数
- types/ - TypeScript 型定義

## 命名規則
- コンポーネント: PascalCase
- 関数・変数: camelCase
- 定数: UPPER_SNAKE_CASE
- ファイル名: kebab-case

## 禁止事項
- any 型の使用禁止
- console.log の本番コードでの使用禁止
- インラインスタイルの使用禁止
```

**Project Rules（新形式）:**

```
.cursor/
  rules/
    coding-style.md    # コーディング規約
    architecture.md     # アーキテクチャ規約
    testing.md          # テスト規約
    security.md         # セキュリティ規約
```

各ルールファイルにはフロントマターでスコープを指定可能:

```markdown
---
description: TypeScript コーディング規約
globs: ["**/*.ts", "**/*.tsx"]
alwaysApply: false
---

# TypeScript ルール
- strict モードを有効にする
- any 型を使わない
```

### 4.2 .cursorignore

AI にインデックスさせたくないファイルやディレクトリを指定する。`.gitignore` と同じ構文。

```gitignore
# .cursorignore
node_modules/
dist/
.env
.env.*
*.min.js
*.map
vendor/
```

### 4.3 プライバシーモード

Cursor にはプライバシー保護のための設定がある。

**設定方法:** `Cursor Settings` > `General` > `Privacy Mode`

| 設定 | 説明 |
|------|------|
| Privacy Mode ON | コードはリモートに保存されず、モデルのトレーニングにも使用されない |
| Privacy Mode OFF | 機能改善のためにデータが使用される可能性あり |

**プライバシーモードの詳細:**
- ON の場合、コードは処理のために一時的にサーバーに送信されるが、保存されない
- SOC 2 認証取得済み
- Business プランでは組織全体で強制適用可能
- 自社 API キーを使用すれば、Cursor サーバーを経由しないことも可能

## 5. 料金プラン

> **注意:** 料金は変更される可能性があるため、最新情報は https://www.cursor.com/pricing で確認してください。以下は2025年前半時点の情報です。

### 5.2 Premium リクエストとは

Premium リクエストは、高性能 AI モデル（Claude Opus 4.6、Claude Sonnet 4.5、GPT-5.3 など）を使用するリクエストのこと。

- **Fast リクエスト**: 即座にレスポンスが返る（Premium リクエストを消費）
- **Slow リクエスト**: 混雑時にキューに入り、待ち時間が発生する（Premium 枠を消費しない）
- Pro プランでは Premium 枠を使い切った後、自動的に Slow リクエストに切り替わる
- 追加の Premium リクエストは従量課金で購入可能

### 5.3 プラン選択の指針

| ユースケース | 推奨プラン |
|-------------|-----------|
| 試しに使ってみたい | Free |
| 個人の日常開発 | Pro |
| チーム開発・企業利用 | Business |
| セキュリティ要件が厳しい | Business（プライバシーモード強制） |

## 6. 初心者向けガイド

### 6.1 最初の一歩

#### Step 1: インストールと基本設定
1. https://www.cursor.com/ からダウンロード・インストール
2. VSCode ユーザーは拡張機能をインポート
3. アカウントを作成しログイン

#### Step 2: プロジェクトを開く
1. `File > Open Folder` でプロジェクトフォルダを開く
2. Cursor がプロジェクトを自動インデックスするのを待つ（初回のみ数秒〜数分）

#### Step 3: まず Tab 補完を体験
1. 任意のファイルを開いてコードを書き始める
2. 灰色のテキストで補完候補が表示される
3. `Tab` で受け入れ、`Esc` で拒否

#### Step 4: Ctrl+K でインラインエディットを体験
1. 編集したいコードを選択
2. `Ctrl + K`（Mac: `Cmd + K`）を押す
3. 「エラーハンドリングを追加して」などと入力
4. 提案された変更を確認し、適用

#### Step 5: チャットで質問
1. `Ctrl + L`（Mac: `Cmd + L`）でチャットを開く
2. 「このプロジェクトの構造を説明して」と質問
3. AI がプロジェクト全体を分析して回答

### 6.2 よくある間違い

#### 間違い 1: コンテキストを与えずに質問する

```
# 悪い例
「バグを直して」

# 良い例
「@file:src/auth/login.ts のhandleSubmit関数で、
パスワードが空の場合にバリデーションエラーが
表示されないバグを修正して」
```

**なぜ重要?** AI は超能力者ではない。具体的なファイル、関数、問題の説明がないと的外れな回答になる。

#### 間違い 2: 一度に大きすぎる変更を依頼する

```
# 悪い例
「このアプリをゼロから全部書き直して」

# 良い例
「まず認証モジュールをリファクタリングして。
具体的には:
1. auth.ts をauth/フォルダに分割
2. JWT トークンの検証ロジックを分離
3. エラーハンドリングを統一」
```

**なぜ重要?** 小さなステップに分割することで、各ステップの品質を確認でき、問題が発生しても切り戻しが容易。

#### 間違い 3: AI の出力を確認せずに全て受け入れる

**対策:**
- 差分を必ず確認してから Apply する
- テストを実行して動作確認する
- Git で変更前にコミットしておき、問題があればすぐに戻せるようにする

#### 間違い 4: .cursorrules を設定しない

プロジェクト固有の規約がないと、AI は一般的なスタイルでコードを生成する。プロジェクトの技術スタック、命名規則、アーキテクチャを `.cursorrules` または `.cursor/rules/` に記述することで、一貫性のあるコードが生成される。

#### 間違い 5: 古いモデルを使い続ける

Cursor は定期的にモデルが更新される。`Cursor Settings > Models` で最新のモデルを確認し、タスクに適したモデルを選ぶ。

### 6.3 効果的なプロンプトの書き方

#### 基本原則

1. **具体的に指示する**: 曖昧さを排除し、期待する結果を明確に記述
2. **コンテキストを提供する**: `@file`、`@folder`、`@codebase` を活用
3. **段階的に依頼する**: 大きなタスクは小さなステップに分割
4. **制約を明示する**: 使用する技術、避けるパターン、パフォーマンス要件を指定
5. **例を示す**: 入出力の例やコードサンプルを含める

#### プロンプトテンプレート

**バグ修正:**
```
## 問題
@file:src/components/UserList.tsx で、ユーザーリストのページネーションが
2ページ目以降で動作しない。

## 期待する動作
ページ番号をクリックすると該当ページのデータが表示される。

## 再現手順
1. /users ページを開く
2. ページ2のボタンをクリック
3. リストが更新されない

## 技術スタック
Next.js 14, React Query, REST API
```

**新機能実装:**
```
## タスク
ダークモード切り替え機能を実装して。

## 要件
- ヘッダーにトグルボタンを配置
- ユーザーの設定をlocalStorageに保存
- システム設定（prefers-color-scheme）をデフォルトとする
- Tailwind CSS の dark: プレフィックスを使用

## 参照ファイル
@file:src/components/Header.tsx
@file:tailwind.config.ts
@file:src/app/layout.tsx

## 制約
- 既存のスタイリングを壊さないこと
- CSS変数ではなくTailwindのdarkモードを使用
```

**リファクタリング:**
```
## タスク
@file:src/utils/helpers.ts を機能ごとに分割して。

## 現状の問題
1ファイルに800行以上の関数が混在している。

## 期待する構成
src/utils/
  date.ts      - 日付関連ユーティリティ
  string.ts    - 文字列操作
  validation.ts - バリデーション
  format.ts    - フォーマット関連
  index.ts     - 再エクスポート

## 制約
- 既存のインポートパスが壊れないよう index.ts で再エクスポート
- 各関数のテストも対応するファイルに移動
```

### 6.4 ベストプラクティス

#### 開発フロー

```
1. 計画: チャットで AI とアーキテクチャを議論
      ↓
2. .cursorrules 作成: プロジェクト規約を定義
      ↓
3. 骨格作成: Composer/Agent で基本構造を生成
      ↓
4. 段階的実装: Ctrl+K とチャットで各機能を実装
      ↓
5. レビュー: AI にコードレビューを依頼
      ↓
6. テスト: AI にテストコード生成を依頼
      ↓
7. リファクタリング: AI と協力してコード品質を改善
```

#### Git との併用

- **こまめにコミット**: AI による大きな変更の前後で必ずコミット
- **差分確認**: AI の変更は `git diff` で必ず確認
- **ブランチ活用**: 実験的な AI 変更は別ブランチで行う

#### コンテキスト管理のコツ

1. **@codebase はピンポイントで**: プロジェクト全体を検索するため、具体的な質問と組み合わせる
2. **@file で最小限のコンテキスト**: 必要なファイルだけを指定して精度を上げる
3. **@docs でドキュメント追加**: よく使うライブラリのドキュメントを登録
4. **チャット履歴の管理**: トピックが変わったら新しいチャットを開始

#### パフォーマンス最適化

1. **軽量タスクには cursor-small / Composer**: Tab 補完や簡単な質問
2. **複雑なタスクには Claude Opus 4.6 / Claude Sonnet 4.5**: アーキテクチャ設計や複雑なリファクタリング
3. **Premium リクエストの節約**: Slow リクエストを活用（急がないタスク向け）
4. **不要なインデックスを除外**: `.cursorignore` で `node_modules` や `dist` を除外
